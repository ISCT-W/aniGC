# aniGC 架构与资料利用方案

当前实现包含工作流 skill、七类模板、本地任务状态、请求预算、版本校验，以及可替换的 API 契约、Gemini / GPT 适配器与 Codex 内置工具的会话衔接。自动反馈检索和 Clip Studio 尚未实现；生成质量需逐任务验证。

## 1. 职责与边界

| 组成 | 职责 | 产出 |
| --- | --- | --- |
| Codex 与工作流 skill | 理解目标、核实资料、写输入、实际看图、选择修改策略 | 参考基线、监修报告与下一步 |
| 外部只读资料工具 | 在用户授权范围内定位并返回资料 | 稳定资源 ID、实际图片或原文 |
| 本地任务工具 | 输入冻结、次数、不可覆盖的文件、恢复、版本检查 | Markdown 记录与少量机器状态 |
| 制作适配器 | 校验后端实际能力并执行一次请求 | 全部可读图片及有限执行信息 |
| 用户验收与反馈 | 对具体版本给出意见，按适用范围校准规则 | 原始评论、版本结论与本地索引 |

没有独立的大模型自我对话循环。Codex 使用 [工作流 skill](../.agents/skills/image-workflow/SKILL.md) 组织工具；代码不会判断图片是否符合角色设定。部署约定参考 [AGENTS.example.md](../AGENTS.example.md)，私有约束保留在本地 AGENTS.md。

## 2. 参考项目与事实依据

正式任务必须配置本地 `ANIGC_REFERENCE_PROJECT_ID`。任务创建及读取时核对项目；更换配置不会迁移或改写已有任务。离线记录使用独立的模拟项目。代码校验项目字段，执行者仍须确认每份远端材料的真实归属。

外部资料工具由使用者在其环境中配置。工具名称、权限、参数和返回字段按实际接口核验；本仓库不发布服务商私有目录、角色资源或接口调查。连接成功、列表非空、下载成功和证据足够分别判断。

切换服务环境时，同时核对端点、该环境的凭据、项目完整 ID 和当前会话已加载的工具；不同环境的同名项目不能视为同一资料库。目标项目未核实前，正式项目配置保持未设置，禁止回退到旧环境。GET、viewer 权限或工具名称不能证明操作没有副作用：可能触发远端抽取、索引或模型处理的入口，需要先核实执行范围并取得对应授权。

| 资料 | 用途 | 使用边界 |
| --- | --- | --- |
| 名称、集数、目录及标签 | 缩小检索范围、定位资源 | 不据此确认不可见的角色细节 |
| 角色图与明确设定文本 | 外观、服装、配饰和武器约束 | 查看实际内容，区分版本、角度和光照 |
| 场景帧或片段 | 动作、持握、互动与空间关系 | 核实画面和真实时间范围 |
| 台本或其他原文 | 特定情境中的行为、表情和台词 | 原文件、可提取正文和结构化结果分别记录 |
| 用户反馈 | 验收偏好与监修检查动作 | 不作为新的官方角色事实 |

参考基线采用 R 来源表与 C 约束表：每条约束绑定实际来源、适用版本、已确认/推断/未知和检查方式，并区分用户硬要求、原作事实、用户质量标准和可调整的创作选择。资料分别标明实际生成输入、监修补充依据或仅用于定位。身份、动作、特效、环境分别判断匹配程度；能取得片段时查看相邻动作阶段，选择适合当前镜头的代表帧，而非默认取首张缩略图。

只保存任务需要的副本或必要原文。临时链接不作为唯一来源；记录稳定 ID、版本、获取时间及必要页码/时间范围。裁剪或缩放保留原图与变换说明。关键资料缺失时停在准备阶段，不能通过反复生成弥补未知设定。

## 3. 历史反馈

原话放在各任务的 `feedback.md`；可复用规则与含真实条目的索引放在本地 `review_knowledge/rules/`；公开 [review_knowledge/index.md](../review_knowledge/index.md) 仅提供路由与格式。真实评论、规则和任务资料不提交到公开仓库。

当前按工作流人工读取与维护，没有自动索引重建或向量数据库：

1. 读取当前任务反馈，以及适用的通用和同角色/版本规则。
2. 再按动作、道具、构图、文字要求和问题类型查找相关案例。
3. 回看原始评论及必要图片，判断采用、不适用或冲突待解决。
4. 将适用内容转成生成约束和监修动作，记录编号与版本。
5. 新反馈保留原话，必要时提炼规则并同步索引；替代关系保留历史，不改写旧轮次结论。

同角色换动作仍可能适用服装规则；跨角色只能迁移通用作画经验。单次偏好不自动推广，当前明确要求优先于历史偏好。反馈校准不涉及模型参数训练，效果需要真实任务评价。

## 4. 生成、监修与验收

新任务／新批次默认最多六次生成/编辑请求，包含首次、已发送失败和重试；显式上限优先，旧批次使用已保存的上限，不随升级扩容或重置。准备、检索、看图与本地恢复不计次数；跨后端和恢复会话不清零。未知请求保守保留次数并阻止再次发送。

每轮保存完整输入、按顺序的参考图与底图、准确模型和设置。API 精确提交文字放在 `submission.md`，人类说明在 `prompt.md`，参数在 `settings.md`；程序不自动解析说明正文。

生成前由 Codex 按 [分镜与提示词流程](../.agents/skills/image-workflow/references/art-direction.md) 从用户叙述和实际资料中主动捕捉关键互动，明确故事瞬间、镜头、逐人动作、效果与环境响应，并检查输入冲突。未指定的非关键细节可依据资料作合理默认，记录选定状态与理由，不要求用户补全分镜。复杂场景可先比较少量文字方案，不需要生图调用。程序不自动做分镜或判断证据充分性。

镜头服务表现力，可采用半身、背侧面、合理遮挡与夸张透视，不强求全身或正脸。监修范围跟随实际可见画面：非明确要求展示且不影响身份／关键动作／互动的画外或遮挡细节记不适用；可见部分核对设定与结构，核心内容不可读则按目标处理。不可见不等于有缺陷，也不等于已经核验。

生成后保存全部可读候选，先判断叙事、构图和动作，再检查角色与局部瑕疵。同一问题沿用 I 编号，写明位置、要求来源、证据、影响和改法。宏观方案不成立就重新分镜／生成，不默认保留旧姿势；局部问题可编辑并回看全图，允许选更合适的历史底图。正确性和适用的叙事／视觉质量目标均成立才通过，不能只满足机械清单，也不能把主观形容词当事实阻断。

只有无阻断、无关键待核验项的准确版本才能进入 `final_output/`。Agent 通过后用户状态为待验收；用户明确接受才记为接受。用户否决保留旧图和评论，继续生成须有明确执行指令。

## 5. 工具与后端

| 文件 | 职责 |
| --- | --- |
| `cli.py` | 命令参数与操作分发 |
| `task_store.py` | 状态、文件、预算、恢复、监修登记与交付 |
| `generation.py` | 读取冻结输入、校验、预留、一次发送与结果收录 |
| `config.py` | 本地参考项目、独立图像模型和按需读取凭据 |
| `backends/types.py` | 后端无关的请求与返回契约 |
| `backends/__init__.py` | 显式后端选择；未实现路线拒绝执行 |
| `backends/gemini.py` / `gpt.py` | 各 API 参数校验、请求构造和响应解析 |
| `backends/common.py` | 单次 HTTP 传输、禁止重定向与图片文件头检查 |
| `backends/codex_image.py` | 会话工具输入校验；不发送 HTTP 请求 |

Gemini API 已实现，使用单次请求，不隐藏重试或切换后端。GPT Images API 已通过同一执行器接入；codex-image 已接入本地准备、校验、手工预留和结果登记，由 Codex 会话调用 image_gen；Python 不代发。Clip Studio 为预留路线。桌面绘画未来需保留可编辑工程与导出图，不将普通画笔操作当作生图 API 请求。

API 由 `generate --execute --evidence-ready` 内部预留次数，不重复手工 reserve。收到结果时先保存预期文件、校验值与完整性，再写产物；文件已完整暂存时可以 collect，不重新调用生成器。未知远端结果未必能够自动取回。

具体命令见 [本地工具](local-tools.md)，模型、输入能力与失败处理见 [生成后端](generation-backends.md)。

## 6. 记录与验证

任务使用 Markdown、原始图片和一个 `state.json`。原始请求、输入快照、产物、监修和用户意见按版本保存；README、执行摘要和验收汇总由状态生成。文件锁与原子写入保护本地计数，不承诺远端恰好执行一次。

版本检查可以发现文件变化，不能证明实际看过图、证据充分或判断正确。授权、证据就绪、监修结论和用户是否接受仍由执行者根据实际信息登记。

离线测试覆盖预算、失败与未知请求、并发、恢复、输入变动、逐图交付及适配器响应。尚需验证真实参考遵循、修改成功率、非目标区域退化和用户验收一致性；这些实验只在用户明确启动生成时执行。
