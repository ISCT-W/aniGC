# 资料使用与证据基线

生成前整理资料、监修需要补证据或核验新接口时读取。项目范围遵守 skill 入口与本地工作约定；以下检索与判断由 Codex 执行，工具只提供其实际支持的查询和读取能力。

## 按需求检索角色与场景

不要只搜索角色名字。先把用户要求中需要依据的部分拆开，再用仍适用的本地基线覆盖已有证据，针对缺口查找：

| 需求 | 查找及核验重点 |
| --- | --- |
| 角色与版本 | 身份、服装／形态／时期，以及本次可见的外观、配饰和武器细节 |
| 场景与动作 | 相似环境、姿势、持握、接触或空间关系；用户指定原作场景时核实相应集数、时间范围和画面 |
| 招式与特效 | 分角色检索招式名／别名、动作描述、武器轨迹和效果；外观图不能替代动作或特效依据 |
| 互动与台词 | 人物关系、特定情境中的行为与表情、指定台词；按需读取对应台本或片段上下文 |

按需求使用角色名／别名、动作或环境描述及工具支持的筛选条件，不要求每个任务查询所有资料类型或下载整段视频。候选有用时继续看实际帧、片段或原文，确认其支持的是哪些要求；标题、摘要、排名和标签不能代替核验。

## 场景匹配后怎样决定

匹配程度针对本次需要借鉴的场景与动作，不表示角色全部设定已核实。只在查询正常完成、相关候选已按需读取后作以下判断：

| 结果 | 生成与监修策略 |
| --- | --- |
| 完整匹配 | 已核验场景、动作与适用版本符合需求，按用途采用证据；仍遵守用户构图和创作目标，不因命中而自动照搬原画。用户明确要求复刻时才按其指定范围还原。 |
| 部分匹配 | 逐项说明可借鉴与不适用的部分。例如角色设定图支持服装、另一片段支持握持，再按用户要求组合；不把其他时期的服装、其他角色的特征或整张图的构图一并移入。尚未证明的部分不能写成已确认设定。 |
| 无匹配场景 | 仅表示本次记录的查询范围内没有取得适用场景。普通原创背景或动作可按用户意图创作，但必须保留足够的角色、服装、武器和行为依据，并注明原创部分；不能退化为无角色依据的生成。 |

用户要求准确复现原作场景、服装或动作时，缺少影响该目标的关键证据就记录阻塞，不以原创内容补齐后声称复刻完成；此规则同样适用于部分匹配。正常检索零命中不代表原作中不存在该场景。工具不可用、调用失败、链接过期、图像或正文不可读属于未核验／读取受阻，不能归为“无匹配场景”。

在 reference 模板中简要记录实际查询范围、匹配程度与理由、采用的 R 证据及用途、原创部分和关键缺口；无需另建逐条请求日志。

## 动作片段与代表帧

动作和特效分别判断完整／部分／无匹配，不以环境已命中替它们通过。优先查角色＋招式／别名，按需放宽为同角色相似发力、持握或运动方向；再找同一风格的特效表达，仅迁移被证据支持的维度。别人的招式不能直接挂到目标角色名下，检索词的别名归一化不修改用户原话。

有短片时先看必要上下文，再取发力前、主要动作、回收等相邻时刻供核验，选动作清楚且适合当前机位的一帧作为生成输入；不机械使用第一个缩略图、最亮特效帧或任意中间帧。记录实际查看的时间点、抽样范围、所选帧理由；抽样不能声称逐帧看完整片段。单帧只支持姿态和瞬间效果，不能证明运动起点、方向或因果。

刀光、碰撞火花、呼吸特效与真实环境元素分别识别。核实刀／身体与特效的相对关系、延伸轨迹、粗细变化、配色、纹样和遮挡，不预设特效必须贴剑尖、包住剑身或形成闭合弧。查询范围受可检索集数影响，未索引视频不可当成已搜过；不得为补缺口擅自触发远端处理。

发现动作或特效缺口时补查并记录，不能用“未指定招式名”免除对原作表达的核验。用户要求原作准确性时，普通动作的部分匹配不够证明命名招式。普通原创动作的回退仍按前表和本地质量要求处理。

## 先确认内容，再分配用途

连接可用、目录数量、搜索命中或 `pending` 字段均不能证明资料足够。使用当前可调用工具的真实定义，不构造接口字段或资源 ID。列表和摘要用于定位；视觉事实需要看实际图片，文字事实需要读原文片段。网页曾看过资料不等于已经保存了本次可复核的输入。

在输入表逐张绑定“对象及版本 → 控制特征 → 禁止迁移内容”，并核对编号与实际图片顺序。人物与其商品不可只用同一个角色名指代；裁切保留原图、区域和用途，避免把配件、表情或背景带给错误对象。只供监修的图不自动全部提交给模型。

将每份资料标为以下一种或多种用途：

| 用途 | 选择标准 |
| --- | --- |
| 实际生成输入 | 与目标角色版本直接相关的清晰图片、必要设定文字，以及经核验的场景／动作参考；实际提交时记录顺序、作用和不应迁移的内容 |
| 监修补充依据 | 其他相关视角、动作上下文、台本原文或允许偏离，保留对应来源位置 |
| 仅用于定位 | 视频名、集数、搜索摘要、标签和目录元数据，不将其直接写成角色事实 |

“主图”只表示存储角色，可能是表情或多视角设定图。检查图片实际内容、服装版本和视角后决定用途，不按字段名猜。拼图需确认是否混有不同形态；裁剪时保留原图、区域和用途。不同光照不自动构成不同配色，资料冲突不能用多数投票或平均颜色解决。

台本支持特定情境中的行为、表情和台词，不能凭空证明服装细节；明确设定文字可以支持其确实描述的细节。PDF 原文件可读、文字已提取与结构化完成分开记录。未执行的 OCR、解析或视频读取不得写成已完成。

## 提交前固定验收边界

把当前任务标准写入现有 C 约束表，在第一次提交前区分严格保持、允许变化和表达目标。每条绑定对象/部位、版本、来源、核对方法与不可读时的处理；合理默认与用户硬要求分开。标准随 reference.md 冻结，不只藏在生成 prompt 中。

- 固定造型商品：轮廓结构、固定姿势、脸部设计、配色分区、配件、持握和连接关系严格按所选证据保持。人物与同名商品分别标识，商品的固定姿势不限制场景人物的动作设计。
- 允许变化：光影、符合结构的透视、合理遮挡与约定的二次元材质。投影轮廓随透视变化不等于结构改变；不得据此改变造型或隐去用户要求展示的内容，不要求逐像素相同。
- 表达目标：明确画面应让观众读出的情绪、互动或展示重点；成图仍需核对。实现目标的机位、姿态等自设手段可以调整，不把它们全部变成硬性约束。

关键细节不可读时先补局部检查；原图确实不足则下一轮调整展示尺度、构图或支持的输出设置，不在验收时临时接受“小尺寸可简化”。非关键画外部位沿用不适用规则。基线改变须区分用户变更、证据纠错、创作选择调整并记录原因；用户硬要求只能由用户改变，不因失败次数增加而降低，旧轮次不覆盖。

## 保存 R 来源与 C 约束

使用 reference 模板。R 来源绑定项目、资源类型及正确 ID、获取时间、实际内容、服务端版本（若有）和本地内容校验值。没有服务端版本号时明确本地校验值只标识保存的内容。未提供的页码、时间范围、版本等写未知，不用元数据的零值伪造定位。

C 约束逐项指出依据 R、角色／服装／时期、已确认／推断／未知、检查方式及用户允许的偏离，并区分用户硬要求、原作事实、用户质量标准和 Codex 创作选择。用户创作要求标为用户来源；历史反馈标为反馈来源，两者不冒充服务端设定。单张参考证明其中可见状态，可以支持用户未指定细节的合理默认，但不自动变成所有场景的通则，也不要求成图露出同一部位。Codex 记录选用状态及依据，保留可调整性；未指定不意味着不能自主决定。只记录可核验的依据和决策，不保存内部思维过程。

基线一旦用于某轮便保留对应快照：任务 references/reference.md 是准备入口，工具将选用版本复制为该轮 reference.md，输入图按顺序复制到该轮 inputs/。补资料另记修订，并让下一轮引用新版本。生成器输入与监修引用必须能回到当时的实际内容，不静默修改旧轮次依据。工具保存副本和校验值不能替 Codex 判断资料是否充分。

后续轮次先复用可读且版本仍适用的本地证据，不每轮重新搜索全部资料。角色／场景要求变化、出现新疑点、已有证据不足或副本不可用时，针对相应缺口补查；需要远端内容而临时链接失效时按稳定 ID 重新获取。记录补查原因和基线修订，不把复用本地文件说成程序已自动更新缓存。

## 缺口如何处理

按目标画面判断是否足够，不要求所有目录非空或全部视频完成。资料未取得、版本冲突、可见关键细节无法核验时，记录缺口和可行的下一步；必要问题未解决前不生成。只有依据已充分、生成器未遵循时才通过修改 prompt 或编辑来修正。

只保存任务需要的资料；签名 URL、凭据和无关库内容不进入模板。图像资产、角色、视频和片段的稳定 ID 应按类型使用，不能互相替换。资源存在、已登记资产、解析成功与实际图像可读分别核实；新接口的字段以交付后的真实定义为准。
