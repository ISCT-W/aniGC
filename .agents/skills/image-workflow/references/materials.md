# 资料使用与证据基线

只在整理本次资料或核验新接口时读取。本文件说明实际取得资料后的处理方法；图文可读性按使用环境核验。项目范围遵守 skill 入口与本地工作约定。

## 先确认内容，再分配用途

连接可用、目录数量、搜索命中或 `pending` 字段均不能证明资料足够。使用当前可调用工具的真实定义，不构造接口字段或资源 ID。列表和摘要用于定位；视觉事实需要看实际图片，文字事实需要读原文片段。网页曾看过资料不等于已经保存了本次可复核的输入。

将每份资料标为以下一种或多种用途：

| 用途 | 选择标准 |
| --- | --- |
| 实际生成输入 | 与目标角色版本直接相关的清晰图片、必要设定文字；实际提交时记录顺序及作用 |
| 监修补充依据 | 其他相关视角、动作上下文、台本原文或允许偏离，保留对应来源位置 |
| 仅用于定位 | 视频名、集数、搜索摘要、标签和目录元数据，不将其直接写成角色事实 |

“主图”只表示存储角色，可能是表情或多视角设定图。检查图片实际内容、服装版本和视角后决定用途，不按字段名猜。拼图需确认是否混有不同形态；裁剪时保留原图、区域和用途。不同光照不自动构成不同配色，资料冲突不能用多数投票或平均颜色解决。

台本支持特定情境中的行为、表情和台词，不能凭空证明服装细节；明确设定文字可以支持其确实描述的细节。PDF 原文件可读、文字已提取与结构化完成分开记录。未执行的 OCR、解析或视频读取不得写成已完成。

## 保存 R 来源与 C 约束

使用 reference 模板。R 来源绑定项目、资源类型及正确 ID、获取时间、实际内容、服务端版本（若有）和本地内容校验值。没有服务端版本号时明确本地校验值只标识保存的内容。未提供的页码、时间范围、版本等写未知，不用元数据的零值伪造定位。

C 约束逐项指出依据 R、角色／服装／时期、已确认／推断／未知、检查方式及用户允许的偏离。用户创作要求标为用户来源；历史反馈标为反馈来源，两者不冒充服务端设定。只记录可核验的依据和决策，不保存内部思维过程。

基线一旦用于某轮便保留对应快照：任务 references/reference.md 是准备入口，工具将选用版本复制为该轮 reference.md，输入图按顺序复制到该轮 inputs/。补资料另记修订，并让下一轮引用新版本。生成器输入与监修引用必须能回到当时的实际内容，不静默修改旧轮次依据。工具保存副本和校验值不能替 Codex 判断资料是否充分。

## 缺口如何处理

按目标画面判断是否足够，不要求所有目录非空或全部视频完成。资料未取得、版本冲突、可见关键细节无法核验时，记录缺口和可行的下一步；必要问题未解决前不生成。只有依据已充分、生成器未遵循时才通过修改 prompt 或编辑来修正。

只保存任务需要的资料；签名 URL、凭据和无关库内容不进入模板。图像资产、角色、视频和片段的稳定 ID 应按类型使用，不能互相替换。资源存在、已登记资产、解析成功与实际图像可读分别核实；新接口的字段以交付后的真实定义为准。
