# 监修、修改与两级验收

生成后或用户单独请求审图时读取。使用 review 模板，在同一轮文件中列出全部候选，并为每张图填写独立检查结果。没有实际查看图片时，只能记录未执行或待核验。

## 查看什么

先定位准确图片版本与参考基线，再查看全图和必要局部。先在整体尺度检查故事和动作，再检查设定与局部缺陷；按用户要求、叙事与视觉表达、角色一致性、行为性格、构图作画、明显生成瑕疵、修改回归七个维度记录观察。角色、服装、武器及行为判断要能回到具体 R／C 依据；不要把审美偏好当成设定冲突，也不要机械用写实人体标准否决约定的风格化表达。

整体检查写明：谁在做什么、对方怎样回应、视线和受力是否支持互动；主体层级与空间深度是否服务用户目标；人物动作是否无理由地镜像、僵硬重复，效果是否只是装饰包边。不要只检查“人数对、张手了、有火有水”。参考 [分镜与动作](art-direction.md) 判断问题，并回到动作／特效帧核对。所谓“AI 感”应拆成这些可指出位置的表现，不判断生成来源。

错字、乱码、多余肢体、错误遮挡、物体融合、武器或服装结构错误等，指出图片位置与实际表现。检查实际可见画面，不把参考图上的全身检查清单变成镜头必须展示的清单：

| 画面情况 | 怎样记录与判定 |
| --- | --- |
| 画外或被合理遮挡，非用户明确要求展示且不影响身份／关键动作／互动可读性 | 该局部记「不适用（未呈现／合理遮挡）」，不造缺陷或关键待核验，不为检查它拉远或改为正脸 |
| 部分可见 | 核对可见轮廓、纹样、连接和遮挡关系；隐藏部分不补想象，不宣称已经核验 |
| 本应可读的可见细节因模糊或资料不足无法判断 | 如实记「无法判断」，仅在影响用户要求、可见关键设定或核心互动时阻断 |
| 身份／关键动作／互动已经不可读，或用户明确要求展示的内容被省略 | 按实际目标记录问题，不能用「被遮挡」免除要求 |

半身、背侧面和夸张透视本身可以通过；检查可见部分是否遵守设定及当前画风中的透视、结构和遮挡关系，不以每只脚、每根手指或正脸缺席为错误。裁边或换镜头形成新版本时仍单独监修，旧图与当时结论保留。

生成 prompt 不是全部验收标准。即使 prompt 没提到某个明显错误，仍须记录。局部修改后检查整张图：手修好但脸、服装或背景退化，不算整体修复完成。

按本轮基线区分原作约束、局部借鉴和原创部分。普通原创场景不因未找到同一原作画面而判错，仍检查角色依据、用户要求与构图作画；指定原作复刻则逐项检查相应证据，不把相似场景视为准确复现的证明。

## 怎样记录问题

同一问题跨轮保留 I 编号，分别记录每张候选的状态。写明位置、实际表现、预期表现和 R／C／反馈依据、影响、阻断或建议、具体改法及需保留的内容。重复出现的旧问题标为回归；不能将生成工具声称“已修复”直接抄成监修结果。

用户硬性要求、确认设定和明显作画／文字错误构成阻断。用户已明确要求的叙事、动作特征或视觉表现同样参与通过判断：与该目标冲突的核心问题不能因为属于审美就一律降成建议。需给出具体表现与适用用户／反馈依据，不能只写“不够震撼”。对称、平视或单纯姿势本身不是错误；图标、合影、仪式画面或用户要求时可能正合适。无明确标准的可选审美优化仍为建议。

每个阻断都复核其来源与重要性。用户没显式指定的细节，Codex 根据实际资料与情境选定状态并用于生成是合理行为；不要把“用户未指定”本身当成选择错误。生成器未遵从该选择时，检查偏离是否破坏所选状态、用户意图、已确认事实或质量目标，决定修正还是接受合理替代，不机械忽略全部自定要求，也不把它们全升级为用户硬要求。新判断追加复核说明，不覆盖旧输入或当时结论。局部细节有多种合理解释时记录不确定性，影响不大则不升级为关键待核验。新缺陷可触发人工补查相关历史反馈，流程见同目录 feedback.md；没有相似反馈不是通过理由。

选择下一轮时可回到更合适的历史底图，记录父轮次和候选，不默认最新结果最好。局部编辑只有在后端实际支持时使用，记录底图／遮罩与保持区域；需要重生成时说明具体原因。发现版本冲突、动作依据不足或新可见细节无法核验时，按 [资料使用](materials.md) 回到对应缺口补查；已有证据仍适用就直接复核，不每轮全量检索。记录补查结果及基线版本，关键问题未解决前保持待核验／不通过，不能以反复改写 prompt 掩盖缺口。

## 什么时候通过

逐图判定，不能让一张通过候选替同轮其他图背书。通过须同时满足两类条件：用户要求与原作事实／作画正确性成立；适用于本任务的叙事与视觉质量目标成立。不能用细节正确抵消故事不可读，也不能用视觉冲击掩盖角色错误。已执行必要检查，没有阻断问题或影响验收的关键待核验项，并复查上轮问题及全图回归。每项质量判断需有画面证据，不能只打综合分；可保留不阻断交付的建议与检查局限。

保存监修文档不等于通过；字段齐全、哈希一致或多 Agent 同意也不能代替实际判断。有收益时可安排独立 Agent 复核，真实记录是否执行及其证据，由 Codex 汇总判断。

## 交付准确版本

先读仓库根 `docs/local-tools.md`，仅使用其中已经实现的记录、状态和交付动作。报告可以包含所有候选，但每张候选的通过／不通过／待核验分别登记，状态各自绑定准确图片和对应报告的内容校验值。首次登记保存为该轮 review.md，之后的另一候选登记或重审另存 review-v002.md 等版本；可复用同份多候选正文，但不得覆盖已经登记的报告。

交付依据同时绑定图片内容与报告版本。改图、修正判断、修改报告或后处理后，重新核验并登记新版本，不能手改旧报告后继续沿用通过标记。每轮以保存的 reference.md 快照为准，不因任务级基线后来更新而悄悄改判。

`final_output/` 仅放 Agent 通过的准确版本和验收说明，初始用户状态为待验收。用户明确接受才改为通过；要求修改为需修改；没有回复不能推断接受。用户否决的旧交付版本留存并标明需修改，新版本另存。未通过候选保留在轮次目录，不以“目前最好”冒充最终结果。

展示实际图片及可打开记录，说明 Agent 结论、用户状态、已用次数、主要修正和剩余局限。额度用完后仍要完成已返回图片的监修与保存；停止的是下一次生成请求。
