# 分镜、动作与提示词

在场景生成准备、宏观返工或用户要求提升视觉表达时读取。目标是让正确的角色在一个可读、有情绪的瞬间行动；详细程度以消除关键歧义为准，不以字数、形容词或参考图数量衡量质量。这里只规定工作方法，具体审美范围以当前用户要求和适用历史反馈为准。

## 导演阶段的输入与完成条件

输入是用户的自然语言目标、已确认的 C 约束和当前可用参考；不要求用户先写分镜。按“理解意图 → 选择单一瞬间 → 安排视觉主次和逐人动作 → 检查可行性 → 写入实际提交文字”完成方案，保存到现有 prompt.md。商品展示、肖像等无复杂剧情的任务也明确观看重点，不强加剧情。

提交前检查关键对象在交付尺寸下是否足够大、必须展示的设计是否被遮挡、手与物体接触是否合理，以及视线/手势是否互斥。风险须对应处理决定，不能只写“注意细节”。证据不足先补证；镜头设计导致关键细节不可读时调整方案，不预先允许模型省略细节。允许的透视与材质变化不得改写固定商品造型，人物姿态则按任务允许范围设计。

导演输出是可执行方案，不是通过结论。生成后仍独立核对画面是否表达了目标；具体镜头选择可调整，用户硬要求不随修改而降低。

## 先决定画面在讲什么

在 prompt 模板的「导演方案与创作选择」中简要记录：

1. **故事瞬间：** 主动从用户描述的冲突、人物关系与已核验资料中捕捉最有表现力的事件，补足用户没有写成分镜的互动因果；不要求用户事先说明每个故事细节。明确谁想做什么、谁在阻止或回应、这个瞬间将怎样影响其他人的动作。例如用户说“第三人试图阻止双方”，可自主选取介入即将改变对决的瞬间，不只安排第三人站在中间。静态图选一个清楚的动作阶段，不同时要求尚未挥刀和已经击中。记录采用的演绎及依据，不冒充原作剧情；仍保留用户指定的角色、行为与场景，不擅自更换关系或强加结局。
2. **镜头与视觉重点：** 第一眼看哪里、随后视线怎样经过人物互动；景别、机位、前中后景、遮挡、留白与尺寸服务这个目的。左右站位不要求等大、等距、镜像；「在两人中间」不等于画布几何中心。保留用户规定的屏幕左右和关键可见特征。
3. **逐人动作：** 每人分别写动作意图、身体朝向与动作线、重心、武器方向和彼此回应；根据实际景别选择可见的肩髋、手势、支撑脚或视线信息。内部构思可以考虑整体受力，不要求把全身画出来供检查。服装相似或同用剑不代表共用一个姿势。只在资料支持时称为角色特有招式；原创动作明确标注。
4. **环境反应：** 选择镜头实际能表现的响应，例如可见的雪痕／飞溅、衣摆／头发的滞后、光线与遮挡。表情和情绪可以通过可见的眼神、下颌、肩背、手势与姿势表达，不强求正脸或所有部位同时出现。风、雪和布料方向若不同，应有可理解原因。

复杂多人动作可先比较 2–3 个简短文字分镜，择一说明理由；简单画面不必凑数。默认由 Codex 决定非关键选择并继续，不增加逐轮审批。相机倾斜、广角、夸张透视、粒子或噪声均不是必选项；刻意不对称也可能破坏清晰度。

**镜头服务表现力，检查范围跟随实际画面。** 允许半身、近景、背面／侧面、合理遮挡和夸张透视，只要角色身份、关键动作及互动可读，可见部分遵守设定。不得为了方便逐项核查而默认露全身、露脚、露所有手指或改成正脸。非用户明确要求展示、且不影响关键表达的画外／遮挡部分不列为缺陷或关键待核验，也不强迫扩大镜头；可见但模糊、结构矛盾或缺证的部分仍按 [监修](review.md) 判定。用户明确要求展示的内容不能因换镜头省略。

用户未指定的非关键细节，可根据实际参考和叙事目的选择一个连贯状态，说明采用的来源与理由并执行；不需要因用户没逐项描述而暂停或否定合理默认。这是可调整的创作决定，不是全角色通则，也不要求所有可用参考图都呈现同一状态。

## 原作动作和特效需要各自的证据

按 [资料使用](materials.md) 检索和观看片段。为每位角色选择有代表性的动作帧；用相邻时刻核实发力方向、持握和动作阶段。能取到片段时查看动作前后，只有单帧时只陈述可见姿势，不声称验证了运动轨迹。

特效描述至少包括：与刀刃／刀尖／身体的可见关系、运动或延伸方向、形状语言和配色、遮挡层次、与其他特效及接触点的关系。区分刀光、碰撞火花、呼吸法轨迹和场景中的火／水；不能仅因红色或蓝色就认定某一招式。不能把一种招式的效果或单帧现象推广成所有招式的规律。

角色身份图、动作帧、特效帧、环境图分别指定用途和禁止迁移内容。必要时从已读原图做有记录的裁剪，减少竹筒／表情／服装版本等互相干扰；相邻帧可仅供监修，不必全送。采用紧凑且无矛盾的参考集，不因后端支持多图就填满输入。

缺少准确招式证据时保留「未核验」，不能仅写得更像原作就当成已确认。普通原创动作按已约定的完整／部分／无匹配策略处理；若当前要求必须忠于具体原作招式，关键缺口未解决前不提交生成。

## 写进实际提交文字

先讲一个连贯的场景，再补角色与技术约束。完整输入覆盖以下必要内容，但不强制固定字数或堆砌段落：

- 画面用途、故事瞬间和主要情绪；用户不可变要求。
- 具体景别、机位、空间深度、视觉重点及角色相对位置。
- 每人的动作、视线、武器／接触关系，与经核实的参考对应。
- 特效的形状、轨迹、层次和环境响应；事实与原创设计分开。
- 选定版本的可见角色特征、每张输入图的编号与用途；不迁移的元素。
- 动画画风的线条、明暗与色彩安排、比例、文字要求；编辑时明确本轮修改和应保持部分。

优先使用描述目标状态的句子，保留确有必要的禁项。避免互相冲突的要求，例如同一角色既双手握刀又用手抓衣领；或同一镜头既极近特写又要求三人全身同样清晰。泛用「cinematic」「masterpiece」「降低 AI 感」不能代替镜头与动作说明。

提交前检查要求来源：

| 来源 | 处理 |
| --- | --- |
| 用户硬性要求 | 不擅自改动；必要歧义才交给用户 |
| 已确认原作事实 | 绑定实际 R／C 与适用版本 |
| 用户质量标准／历史偏好 | 写成可观察检查动作；按范围应用，允许当前指令覆盖 |
| Codex 创作选择 | 用户未指定时可依据资料与叙事自主选择，记明理由并执行；未指定本身不是错误或阻塞。保留可调整性，不升为用户硬性要求或通用原作设定 |
| 未知／推断 | 明确标注，不冒充准确招式或版本事实 |

## 监修先判断方案，再精修

按 [监修](review.md) 先做整体阅读，再放大检查。不看说明能否读出谁在攻击、阻止、犹豫或反应？去掉醒目的特效，动作和人物关系是否仍然清楚？不用实际抹除图片，可在原图上观察轮廓与受力。多人姿态、大小、特效是否机械重复；重复是用户指定设计还是没有发挥作用的默认值？

若主要问题在故事／构图／动作，返回导演阶段调整；不能只修眼睛和装饰后宣称接近完成。每次按 [修改诊断](review.md#修改诊断与下一轮)说明问题、原因假设、输入变化及保留内容。局部编辑优先保留已成立的结构；确需整体重生成时说明局部编辑为何不足，继承基线、成功要素与失败记录，不把重生成变成无诊断抽样。每轮复核全图及参考冲突，不只把原句写得更强烈。

## 提示词研究怎样进入流程

本次实际检查的来源、提示词与成图观察及局限见 [方法调查](prompt-study.md)，需要审核依据或更新研究时读取。

本流程参考了 [Google 的 Nano Banana Pro 指南](https://blog.google/products-and-platforms/products/gemini/prompting-tips-nano-banana-pro/) 对主体、动作、构图及参考用途的明确区分，以及 [Google Developers 的场景和漫画示例](https://developers.googleblog.com/how-to-prompt-gemini-2-5-flash-image-generation-for-the-best-results/) 对连贯场景描述的使用。这些是方法来源，不是角色设定依据，也不证明某个提示词对当前模型必定有效。

当新风格、模型能力或反复失败确实需要补课时，找同时公开实际输入与成图的第一手案例，比较具体表达怎样落到画面；记录有用方法与失配，少量摘录，不收藏冗长提示词大全。正文长度不是目标；不照搬摄影参数到动画，也不把案例中的文字、人物或比例带入用户作品。资料库中的角色事实仍只来自授权项目。
